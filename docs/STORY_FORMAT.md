# 主线与闲聊配置

资源目录：`src/main/resources/assets/lonya_plush/story/`。主线分别读取 `chapter1.json` 至 `chapter5.json`，日常闲聊读取 `causal.json`（文件名按此拼写）。主线每个文件是单个章节对象，修改后重新构建并同时替换客户端、服务端 JAR，重启生效。

## 日常闲聊：causal.json

文件内容是一个数组。每次点击时，服务端先按玩家当前好感度筛选，再从符合条件的条目中等概率随机选择一条，在玩偶菜单直接显示文字和对应表情。同一条可以连续抽到。

```json
[
  {
    "text": "回来啦，先坐一会儿？",
    "expression": "hello",
    "min_affection": 0
  },
  {
    "text": "刚才还在想你会不会来……",
    "expression": "shy",
    "min_affection": 30,
    "max_affection": 80
  }
]
```

| 字段 | 作用 |
| --- | --- |
| `text` | 必填，显示的闲聊文字 |
| `expression` | 对应 `textures/story/` 的表情 PNG 名，不写扩展名；省略时为 `hello` |
| `min_affection` | 最低好感度，包含该值；省略为 0 |
| `max_affection` | 最高好感度，包含该值；省略时无额外上限 |

表情可用：`hello`、`calm`、`angry`、`idea`、`puzzled`、`shy`、`sorry`、`surprised`。范围不能为负数，最高值不能小于最低值。30–80 的文本在好感度恰好为 30 或 80 时也有概率出现，29 和 81 时不会出现。抽取使用本次奖励结算前的好感度。

建议至少保留一条不设置上限的通用文本，覆盖所有好感度。若当前范围内没有文本，界面提示无可用闲聊，本次不发放奖励，也不更新聊天时间。

首次闲聊，或者距上次闲聊已满 60 秒时，本次闲聊增加 1 点好感度。每次实际闲聊都更新上次闲聊时间；一分钟内再次点击仍会显示文字和表情，但不增加好感度，并重新开始这一分钟的计时。该时间按玩家跨玩偶、跨重进保存；独立于章节冷却配置，离线时间也计入。

## 主线：chapter1.json 至 chapter5.json

每个文件对应一章，含 `title`、`summary`、`lines`。对白顺序写在 `lines` 数组中；任意一条对白可以带 `choices`。每个选项有自己的 `lines`，读完后自动回到选项所在对白后面的共同对白；分支内也可继续配置选项。选项数量不限，界面空间不足时分页显示。

下面是一章的示例对象，保存为对应章节的 JSON 文件即可；当前游戏资源中第四章已经提供完整可编辑实例：

```json
{
  "title": "第4章 · 一通电话",
  "summary": "聊天、回答，再回到共同对白。",
  "lines": [
    {
      "id": "phone_question",
      "speaker": "Lonya",
      "text": "对话1：我是不是说太多了？",
      "choices": [
        {
          "text": "选项a：我挺喜欢听你说的。",
          "affection": 5,
          "unlock_fifth": true,
          "lines": [
            {"id": "phone_a1", "speaker": "Lonya", "text": "对话a1"},
            {"id": "phone_a2", "speaker": "你", "text": "对话a2"},
            {"id": "phone_a3", "speaker": "Lonya", "text": "对话a3"},
            {"id": "phone_a4", "speaker": "旁白", "text": "对话a4"},
            {"id": "phone_a5", "speaker": "Lonya", "text": "对话a5"}
          ]
        },
        {
          "text": "选项b：今天先聊到这里吧。",
          "affection": -5,
          "end_route": true,
          "lines": [
            {"id": "phone_b1", "speaker": "Lonya", "text": "对话b1"},
            {"id": "phone_b2", "speaker": "你", "text": "对话b2"}
          ]
        }
      ]
    },
    {"id": "phone_common", "speaker": "旁白", "text": "对话2：两条分支都会继续到这里。"}
  ]
}
```

| 字段 | 作用 |
| --- | --- |
| 对白 `id` | 推荐填写，同章内唯一的稳定标识，用于恢复位置、历史和选项结算记录；省略则按所在路径生成 |
| 对白 `speaker` / `text` | 必填，发言者和内容 |
| 对白 `choices` | 可选，回答数组；省略或空数组表示普通顺序对白 |
| 选项 `text` | 必填，按钮文字 |
| 选项 `affection` | 有符号整数，省略为 0；正数增加，负数减少，玩家总好感度不低于 0 |
| 选项 `lines` | 选择后的独立对白；省略或为空则直接进入共同后续对白 |
| 选项 `unlock_fifth` | 可选，默认 false；true 保留原有的第五章解锁效果，还需读完第四章且好感度达到 100 |
| 选项 `end_route` | 可选，默认 false；true 在本章分支、共同对白全部读完后结束路线，仍可重玩已解锁章节 |

同一玩家对同一章的同一个选择节点，只在首次作答时结算好感度变化，正负变化都记录；重玩可选择不同回答并观看不同分支，但不重复增减好感度。解锁第五章等剧情效果仍按本次选择执行，已经获得的解锁不会被撤销。

不再配置 `expression` 或 `minimum_ms`。主线使用章节 CG；每条自动播放时间由代码按文字长度计算，当前为每字符 100ms 加 1200ms，限制在 1800–15000ms。手动继续和快进无需等待。

分支中断后重开仍从保存的对白继续；历史保留最近 512 条实际读过的对白。修改文字时保留 `id`，调整结构时也尽量保留已有 `id`；改掉某个选择节点的 id 会将它视作新节点。删除正在阅读的节点时保存位置会退回有效位置，删除的历史条目不会再展示。

五章拜访好感度门槛仍为 20／40／60／80／100，并保留前章完成条件。原有第四章的两个选项分别放在第四章最后一条原始对白的 `choices` 中：第一项 +5 并解锁第五章，第二项 -5 并在读完整章后结束路线。可在任意对白上继续添加、修改其他选择。章节的 `lines` 不可为空；不再限制每章固定段落数或总播放时长。
